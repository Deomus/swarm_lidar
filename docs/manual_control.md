# Управление ведущим с клавиатуры

`keyboard_control` передаёт команды уже взлетевшему ведущему аппарату.
Три ведомых продолжают сопровождать его через обработку LiDAR и контроллер
формации. Клавиатура не вооружает аппараты, не выполняет взлёт, не включает
Offboard в PX4 и не сажает группу.

## Подготовка

Соберите пакет `leader_interface` и подключите окружение рабочего пространства.
Запустите симуляцию и подготовьте группу к полёту штатным сценарием. Все
терминалы должны использовать один домен ROS. Нужен работающий узел
`leader_interface`, живые часы `/clock` и телеметрия `/mesh/states`.

Для записи действий настоящего оператора предусмотрен сценарий:

```bash
ROS_DOMAIN_ID=72 python3 scripts/run_scenario.py operator \
  --record-cloud --output log/operator_run
```

Каталог результатов должен быть новым. Сценарий сам выполняет подготовку
и выводит «Ожидание оператора». После этого откройте отдельный терминал,
подключите то же окружение и запустите:

```bash
ROS_DOMAIN_ID=72 ros2 run leader_interface keyboard_control
```

Этот терминал должен принимать ввод с клавиатуры. Перенаправление ввода
из файла или канала не поддерживается. При старте программа запрашивает
ручной режим, когда появляются пригодные часы и состояние ведущего.
Движение разрешается после положительного ответа сервиса `/leader/manual`.

Дополнительно проверяются вооружение ведущего, режим PX4 Offboard (`14`),
пригодность его координат и высота не менее 1 м над нулём карты. Для
штатного мира с землёй на высоте ноль это исключает управление аппаратом
на земле. Во время снижения ниже этого порога будет запрошено удержание.

## Клавиши

| Клавиша | Действие |
| --- | --- |
| W / S | Движение вдоль +X / −X карты |
| A / D | Движение вдоль +Y / −Y карты |
| R / F | Подъём / снижение |
| Q / E | Поворот против часовой стрелки / по часовой стрелке |
| 1 / 2 / 3 | Скорость 0.5 / 1.0 / 1.5 м/с |
| Пробел | Нулевая команда и запрос удержания HOLD |
| Enter | Запрос ручного режима MANUAL после удержания или восстановления данных |
| Esc | Нулевая команда, запрос HOLD и выход из программы клавиатуры |

Начальная скорость — 0.5 м/с, скорость поворота ограничена 0.3 рад/с.
Координаты — `map` ENU: X направлена на восток, Y на север, Z вверх.
Направления клавиш закреплены относительно карты; положение камеры и
поворот ведущего их не меняют. Для движения используется последнее
полученное направление. Сочетания нескольких осей одновременно не задаются.
После смены скорости снова нажмите клавишу направления.

Обычный терминал сообщает символы нажатий и автоповтора, но не сообщает
момент отпускания. Поэтому действие направления сохраняется на 0.25 с
после последнего символа. Затем программа запрашивает нулевую скорость.
Длинное нажатие работает за счёт автоповтора; начальная задержка автоповтора
терминала может оказаться больше 0.25 с и дать заметный перерыв. Короткие
повторные нажатия позволяют задавать движение без этого начального перерыва.

Переход к нулевой запрошенной скорости проходит через ограничения движения
ведущего. Физическая остановка занимает время. Пробел отдельно запрашивает
режим HOLD. Положительный ответ сервиса означает принятие режима узлом
управления; положение и скорость аппарата следует наблюдать отдельно.

Стрелки терминала не используются: их последовательности начинаются с Esc,
поэтому нажатие стрелки завершит программу клавиатуры.

## Защита от старых данных

Команды `TwistStamped` публикуются примерно 20 раз в секунду с текущей
отметкой часов симуляции и `frame_id=map`. Установлен `use_sim_time=true`.
Работа защиты проверяется по независимому монотонному времени системы:

- более 0.25 с без продвижения `/clock` запрещает публикацию команд,
  включая повторную публикацию нулевой команды со старой отметкой;
- повторение одинаковых значений `/clock` не скрывает паузу;
- скачок часов назад или вперёд более чем на 0.5 с запрещает движение;
- телеметрия проверяется по времени измерения и по времени получения;
  допустимый возраст — 0.5 с. Будущие отметки не принимаются.

При потере данных запрашивается HOLD. После восстановления необходимо
нажать Enter и затем заново выбрать направление. Программа не возвращает
прежнее направление автоматически. При остановившихся часах запрос HOLD
может обрабатываться ROS, но движение симуляции продолжится только после
возобновления её времени.

При необходимости параметры можно уменьшить через `--ros-args -p`, например:

```bash
ROS_DOMAIN_ID=72 ros2 run leader_interface keyboard_control \
  --ros-args -p max_speed:=1.0 -p max_yaw_rate:=0.2
```

Скорость выше 1.5 м/с и скорость поворота выше 0.3 рад/с не допускаются.
Контроллер ведущего дополнительно применяет свои ограничения из
`config/leader.yaml`.

## Завершение операторского сценария

Сначала нажмите Esc в терминале клавиатуры. Это завершит только управление
с клавиатуры и запросит удержание ведущего. Затем в отдельном терминале:

```bash
ROS_DOMAIN_ID=72 ros2 service call /scenario/finish std_srvs/srv/Trigger '{}'
```

Сценарий выполнит штатную посадку всей группы и завершит запись. Дождитесь
подтверждения посадки и сохранения результата. Сам запрос завершения ещё
не означает, что аппараты уже сели.

Ctrl+C, SIGTERM и потеря терминала восстанавливают его настройки и запускают
запрос HOLD. Отсутствие ответа HOLD явно выводится в терминал. Прерывание
самого сценария через Ctrl+C считается неполной сессией. У него также есть
ограничение 1800 с реального времени и проверки потери телеметрии/сброса
часов; подробности ошибок сохраняются в результате сценария.

Проверки чистой логики клавиш и таймеров:

```bash
python3 -m pytest src/leader_interface/test/test_keyboard.py -q
```

Автоматические тесты проверяют обработку ввода и защитные условия. Они
не заменяют записанный полёт с участием оператора.
