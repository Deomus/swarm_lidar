# Запись видео симуляции

Обзорная камера снимает трёхмерную сцену Gazebo. Камера нужна только
для демонстрации и не участвует в управлении.

Начальная позиция камеры — `(−3, −16, 17)` м, поворот в сторону положительной
оси Y и наклон вниз примерно на 0,82 радиана. Горизонтальный угол обзора —
примерно 60°. Разрешение — 1280 × 720, частота — 10 кадров в
секунду времени симуляции. Изображения публикуются в Gazebo в теме
`/evaluation/video`.

## Что требуется

Для включения камеры при запуске добавьте `video:=true`:

```bash
ROS_DOMAIN_ID=72 ros2 launch swarm_lidar swarm_demo.launch.py \
  gui:=false lidar:=true video:=true
```

По умолчанию камера выключена. При её включении создаётся отдельная копия
мира в каталоге текущего запуска. Изображение доступно и без окна Gazebo.

Нужны Python-модули `gz.transport13`, `gz.msgs10` и исполняемый файл FFmpeg.
Для Ubuntu 24.04 с настроенными репозиториями Gazebo:

```bash
sudo apt install python3-gz-transport13 python3-gz-msgs10 ffmpeg
```

Запись подключается прямо к Gazebo, поэтому `ROS_DOMAIN_ID` не влияет на неё.
Переменная `GZ_PARTITION` должна совпадать с разделом запущенной симуляции.

Параметр `--follow` получает имена и координаты моделей из обзорного канала
Gazebo и перемещает только камеру к центру группы. Эти координаты используются
для кадрирования видео и не передаются в управление аппаратами. Без параметра
камера остаётся неподвижной. Запросы перемещения ограничены по частоте и
тайм-ауту; при завершении выводится число подтверждённых и неудачных запросов.

## Как записать

Из корня репозитория, после запуска мира с обзорной камерой:

```bash
GZ_PARTITION=swarm_lidar python3 scripts/record_video.py \
  log/formation_demo.mp4 --duration 180 --follow
```

Родительский каталог должен существовать. Скрипт создаёт только новый файл:
существующее видео с тем же именем не перезаписывается. `--duration` задаёт
длительность сбора кадров по реальным часам. Без этого параметра запись длится
до `Ctrl+C`; программа закрывает вход кодировщика и завершает запись файла.

Если FFmpeg установлен отдельно, передайте путь явно:

```bash
GZ_PARTITION=swarm_lidar python3 scripts/record_video.py \
  log/formation_demo.mp4 --ffmpeg /путь/к/ffmpeg
```

Скрипт проверяет формат `RGB_INT8`, размеры, длину строки и размер данных.
Дополнительные байты между строками отбрасываются. Очередь ограничена пятью
кадрами: если кодирование не успевает, старые кадры пропускаются, а память
не растёт без ограничения. При завершении выводятся счётчики полученных,
записанных, пропущенных и некорректных кадров.

В MP4 кадры воспроизводятся с постоянной частотой 10 кадров/с. При замедленной
симуляции, паузах или пропусках итоговая длительность видео отличается от времени
записи по реальным часам. Точные временные отметки измерений следует смотреть
в журналах оценки, а не восстанавливать по номеру кадра.

Контейнер MP4 записывается фрагментами, чтобы уже закодированные фрагменты
оставались доступными при неожиданном прерывании. Если изображения не поступают
30 секунд, скрипт завершится с ошибкой. Проверьте наличие камеры, тему и
`GZ_PARTITION`; при необходимости увеличьте `--startup-timeout`. Файл после
неуспешной записи может быть пустым или неполным — это не готовая демонстрация.
