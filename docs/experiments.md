# Проверки в симуляции

## S1: формации, 20 октября 2026 года

Проверена исходная плавная настройка kp=0.3, max_jerk=8 м/с³,
max_speed=2 м/с. Клин образуют три ведомых: центральный ближе к ведущему,
два боковых дальше позади. Каждый переход сопровождался десятью секундами
дополнительного наблюдения. Все четыре аппарата взлетели, прошли
line → изменение масштаба → line → column → wedge → line и сели.

Исходные локальные результаты: `log/s1_20261020_183720`, запуск симулятора
`log/sitl_20261020_183631`. Журналы не включены в Git; ниже сохранены
измеренные результаты одного прогона, а не статистика нескольких повторений.

При удержании учитывается также остаточное движение после окончания
запланированного перехода. Сырая ошибка LiDAR включает смещение видимой
поверхности относительно центра сферы; контроллер отдельно применяет
приближённую поправку поверхности. Поэтому сырая ошибка LiDAR и ошибка
удержания — разные величины.

Через десять секунд после достижения критерия формы ошибки по LiDAR
составили 0.128/0.026/0.116 м для колонны, 0.057/0.047/0.085 м
для клина и 0.167/0.043/0.095 м для финальной линии. Они отличаются
от ошибки по эталону Gazebo и не означают такой же точности абсолютного
положения.

Критерий завершения S1 требует свежих состояний и подтверждённого
разоружения всех четырёх аппаратов. В этом прогоне `passed_run=true` и
`passed_landing=true`. Минимальная дистанция проверяется по выборкам
с периодом 0.1 с; это не непрерывное доказательство отсутствия сближения.

## S2: ручной вход и потеря связи

Локальные результаты: `log/s2_20261020_184201`, симулятор
`log/sitl_20261020_184200`. Проверены команды ручного входа 0.5, 1.0 и
1.5 м/с, повороты, изменение высоты, остановка и потеря LiDAR-поз на 0.7 с.
Это автоматизированная подача ручных команд, а не управление оператором.

`DATA_HOLD` и недействительные нулевые команды трём ведомым подтверждены
через 0.496 с после начала проверки. После возврата данных восстановлено
удержание линии. Все аппараты сели; `passed_run=true`, `passed_landing=true`.
Этот статус подтверждает последовательность сценария, а не требуемую
точность на всём участке движения.

При активном управлении среднеквадратичная ошибка формы по эталону составила
1.210 м, максимум — 3.628 м, минимальная измеренная дистанция — 2.431 м.
Следовательно, сопровождение на высоких скоростях пока нельзя считать
настроенным: плавные команды дают заметное отставание ведомых. Требуется
отдельная настройка динамического сопровождения с сохранением ограничений.
Остановка подтверждена по командам; время фактического физического торможения
в этой проверке отдельно не измерялось.

После завершения launch штатно остановил собственные процессы, порт агента
8889 освободился.

## S3: маршрут A* и завершение миссии

Первый прогон `log/s3_20261020_184449` остановился с `STATE_STALE`:
собственное состояние ведущего стало недопустимым по свежести. Аппараты
посажены. Этот результат считается отказом, а не успешной миссией.

После уменьшения `waypoint_gain` с 0.5 до 0.25 повтор
`log/s3_20261020_184913` завершился успешно. A* построил маршрут из семи
точек к (6,3,3) м. После `COMPLETE` подтверждены удержание линии и остановка
ведущего. Ошибка ведущего по собственному PX4 составила 0.298 м,
все четыре аппарата сели и разоружились.

За активное управление RMS ошибки формации по эталону составила 0.303 м,
максимум — 0.580 м, минимальная дистанция — 3.718 м. Доля устаревших
LiDAR-измерений — 0.12%. Это один успешный повтор после отказа; для оценки
надёжности нужны дополнительные прогоны. Во время S3 упреждение ведущего
ещё не использовалось.

Остаются повтор S2 после настройки сопровождения, запись rosbag, видео,
проверка повторяемости и итоговая приёмка.
