# Браузерная панель управления

Панель открывается по адресу **http://localhost:8080**. Она подключается
к уже запущенной симуляции, показывает состояние четырёх аппаратов и
позволяет выполнять взлёт, посадку и три сценария ТЗ вручную: строй и
высоту, ручное управление ведущим и маршрут к точке на карте.
Нужны только браузер и установленные зависимости самого проекта.
Отдельная сборка сайта и установка библиотек JavaScript не требуются.

## Проверенные действия

Ниже — проверки предыдущей версии страницы, с кнопками готовых сценариев.
Новая раскладка проверена в Chromium без симуляции: вёрстка на ширине
1440/1024/390 px без горизонтальной прокрутки, отправка команд строя,
высоты и пульта, отсутствие ошибок JavaScript. Полётная проверка новой
раскладки (`check_web_panel.py --flight`) ещё не выполнялась.

Ранее в Chromium проверены обычная и узкая ширина окна, состояние без симуляции
и управление настоящими PX4 в Gazebo через браузер:

- подготовка группы, клин, возврат в линию, удержание и посадка;
- прерывание подготовки с разоружением всех четырёх аппаратов;
- полные сценарии перестроений, маршрута и сопровождения, каждый с посадкой;
- подтверждение строя после выдержки по трём ошибкам LiDAR;
- закрытие вкладки без изменения полёта и остановка сервера с посадкой.

Все штатные прогоны сохранили MCAP. Прерванная подготовка записана как
прерванная, с успешной посадкой. Ошибок JavaScript в успешной полной
браузерной проверке нет; пройдены 348 тестов Python. Компактный результат —
[web_panel.json](../examples/results/web_panel.json). Полные записи
и изображения экрана находятся локально в `log/` и в Git не добавляются.

## Запуск

После сборки проекта в первом терминале запустите симуляцию:

```bash
source /opt/ros/jazzy/setup.bash
source ~/px4_ros_ws/install/setup.bash
source install/setup.bash
ROS_DOMAIN_ID=72 ros2 launch swarm_lidar swarm_demo.launch.py \
  gui:=true lidar:=true stack:=true
```

Во втором терминале из корня репозитория:

```bash
source /opt/ros/jazzy/setup.bash
source ~/px4_ros_ws/install/setup.bash
source install/setup.bash
ROS_DOMAIN_ID=72 ros2 run swarm_lidar web_panel
```

Откройте **http://localhost:8080**. Дождитесь сообщения о подключении всех
четырёх аппаратов. Для другого локального порта добавьте `--port 8081`.
Домен ROS должен совпадать с доменом симуляции.

## Как пользоваться

Вверху — полёт и четыре плитки аппаратов с кнопками **«Взлететь»** и
**«Посадить»**. Первое «Взлететь» начинает сессию с записью: исполнитель
проверяет аппараты на земле, затем выполняет взлёты по очереди нажатий
(до высоты взлёта PX4, 2,5 м). Когда в воздухе все четыре, строй собирается
сам: LiDAR-цели, Offboard, контур, линия. «Посадить» у ведомого сажает
только его — строй переходит в DEGRADED, ведущий стоит; повторный взлёт и
«Вернуть в строй» возвращают аппарат. Ведущий садится последним: пока ведомые
в воздухе, его «Посадить» недоступна, для всей группы — «Посадить всех». **«Удерживать»** останавливает ведущего; ведомые продолжают
держать строй. **«Посадить всех»** завершает сессию с посадкой, во время
подготовки — прерывает её; повторное нажатие не прерывает начатую посадку.
Когда появится **«Группа готова к командам»**, доступны три блока.

**1 · Строй и высота** (сценарий 1 ТЗ). Выберите линию, колонну или клин,
масштаб и время перехода, нажмите **«Применить строй»**. Следующее
перестроение доступно после установления текущего: три ошибки LiDAR меньше
0,6 м в течение секунды; до этого показывается «Занимают места». Перед
перестроением ведущий должен быть в удержании. Перестроение проверяется по
карте; при нехватке места панель покажет причину. Масштаб ограничен
диапазоном 0,75–2: при шаге 4 м места не ближе 3 м друг к другу и к ведущему.
Справа — **высота роя**: введите высоту 2–20 м и нажмите **«Изменить»**.
Ведущий меняет высоту на месте через планировщик (цель в его текущих X/Y),
ведомые следуют.

**2 · Ручное управление** (сценарий 2). Удерживайте кнопку — ведущий движется
относительно своего курса: ↑/↓ вперёд-назад, ←/→ вбок, ↺/↻ поворот, «Выше»/
«Ниже» — по высоте; скорость 0,5 / 1 / 1,5 м/с. Отпущенная кнопка даёт плавное
торможение, **■** — удержание. Ведомые держат курс ведущего. Подробности и
защита от пропажи команд — [manual_control.md](manual_control.md).

**3 · Маршрут к точке** (сценарий 3) — карта ниже.

Если ведомый выбыл (нет LiDAR-позы), строй переходит в DEGRADED: ведущий
стоит, остальные держат места, в ошибках строя показано «выбыл». Если отказ
длится дольше 5 с, мост переводит аппарат в удержание PX4, через 30 с — в
посадку ([autopilot_bridge.md](autopilot_bridge.md)). Когда данные вернулись,
появляется кнопка **«Вернуть в строй»**: она включает Offboard у зависших
аппаратов и при необходимости снова включает строй.

Таблица и вид сверху показывают собственные оценки положения PX4.
Эталонные координаты симулятора в панель не поступают. Измерения LiDAR
по-прежнему используются существующим контуром управления ведомыми.
При пропаже или остановке обновления телеметрии команды блокируются;
потерянные показания помечаются явно. Не запускайте другой исполнитель
сценариев из терминала параллельно панели. Автоматические прогоны S1/S2/S3
запускаются из терминала: `scenario_runner` или `scripts/repeat_scenarios.py`.

После посадки в колонне или клине следующая подготовка повторно ищет цели
по последней полной расстановке, измеренной LiDAR, и плавно возвращает
группу в линию. Для этого трекер должен продолжать работать между полётами.
Если трекер перезапущен или аппараты перемещены вручную, перезапустите
симуляцию, чтобы восстановить исходные позиции и привязку целей.

## Запись и завершение

При включённом **«Сохранять измерения»** записываются сообщения ROS
в MCAP. Облака LiDAR и видео автоматически не записываются. Данные
сохраняются в `log/web/<сессия>/flight`, журнал исполнителя — рядом
в `console.log`. Каталог можно изменить параметром `--log-dir`.

Закрытие вкладки не завершает полёт. Сначала нажмите **«Посадить всех»**
и дождитесь разоружения четырёх аппаратов. Затем остановите панель
сочетанием `Ctrl+C`, после неё — симуляцию. Если остановить сервер панели
при её активном полёте, он сначала попросит исполнитель выполнить посадку
и дождётся его завершения. Неудачная посадка выводится как ошибка.

## Маршрут к точке (сценарий 3)

После подготовки группы и подтверждения текущего строя щёлкните по карте.
Штатный запуск с `lidar:=true` автоматически публикует `/map`: известную
свободную площадку 200 × 200 м с разрешением 1 м. Это описание площадки,
а не построение карты по LiDAR. Визуальные наземные ориентиры не являются
физическими препятствиями. Планировщик оставляет запас от края карты;
точки в этой защитной полосе отклоняются с пояснением в панели.
Колесо мыши меняет масштаб, перетаскивание сдвигает вид. Нажмите
**«Полететь всем роем»**, чтобы отправить цель через планировщик; ведомые
продолжат удерживать формацию. Клик только выбирает место и сам по себе
не запускает полёт. Рой летит на текущей высоте ведущего (после взлёта —
высота взлёта PX4, 2,5 м); координаты X/Y — от −100 до 100 м. Для остановки маршрута используйте **«Удерживать»**.

Удержание и посадка отменяют ожидающую цель. Ответ планировщика сопоставляется
с конкретным запросом, затем проверяется принятие пути ведущим. Ожидание
подтверждения ограничено 10 секундами реального времени. Удержание доступно
и во время ожидания; запоздалый ответ не запускает отменённую миссию.

Сервер слушает только `127.0.0.1`. Он проверяет локальный адрес и маркер
сессии для управляющих запросов; произвольные команды оболочки через
браузер не выполняются. На один домен ROS допускается один сервер панели.

## Проверка разработчиком

`scripts/check_web_panel.py` проверяет страницу в Chromium через Playwright.
Это дополнительная зависимость проверок; для использования панели она
не требуется. Без `--flight` проверяются отображение и ошибки JavaScript.
С параметром `--flight` скрипт действительно поднимает аппараты в уже
запущенной симуляции: подготовку, клин и возврат в линию, подъём роя на 1 м,
удержание кнопки «вперёд» 3 с с проверкой режима MANUAL и торможения,
«■» и посадку. Выполняйте его в том же окружении,
где установлен Playwright и доступен его браузер:

```bash
python3 scripts/check_web_panel.py --flight
```

Отдельная проверка выбора точки с подготовкой группы и обязательной посадкой:

```bash
python3 scripts/check_map_goal.py --flight --prepare --land --output log/проверка_точки  # --prepare: «Взлететь» у всех четырёх
```

Она также проверяет, что высота ведущего у цели совпадает с высотой
в момент отправки цели. Без `--prepare` ожидается
уже подготовленная операторская сессия; без `--land` группа остаётся в удержании.

Изображения экрана и результат проверки сохраняются в отдельный каталог
`log/web_browser_*`; каталоги полётов указаны в `browser_result.json`.

Выбор точки и полёт к ней отдельно проверяются командой:

```bash
python3 scripts/check_map_goal.py --flight --output log/map_goal_check
```

Нужны уже подготовленная группа в ручной сессии панели и Playwright.
Команда действительно отправляет цель и ждёт `MISSION`, затем `COMPLETE`;
после проверки группа остаётся в удержании. Без `--flight` проверяется
только выбор точки. Каталог результата должен быть новым.

В проверке `log/map_goal_live_1/result.json` кнопка браузера отправила
цель около X = 10,0 м, Y = 2,2 м. Все четыре аппарата переместились
примерно на 10,3 м, ведущий завершил 12 точек пути со статусом `COMPLETE`.
Горизонтальная ошибка относительно округлённых координат метки — 0,37 м.
Ошибок JavaScript нет. Это проверка перемещения по X/Y; высота маршрута
в этом прогоне задавалась текущей настройкой планировщика 3 м.
