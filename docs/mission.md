# Планирование миссии

Коэффициент приближения ведущего к точкам `waypoint_gain=0.6` используется
с компенсацией остаточного хода фильтра скорости. Промежуточные точки
на одной прямой удаляются; углы сохраняются. Предел времени участка
учитывает его длину, отсутствие продвижения контролируется отдельно.
Подробности сравнения режимов — в [leader_route.md](leader_route.md).

Последняя точка маршрута сохраняет точные X/Y запрошенной цели, а не центр
её клетки.

Высота маршрута выбирается так: нулевая высота цели означает
`working_altitude` (3 м), ненулевая берётся как запрошенная. Выше
`max_altitude` (30 м) цель отклоняется. Ниже `min_altitude` (2 м) высота
поднимается до 2 м: датчик LiDAR стоит на 1,9 м выше корпуса и ищет ведомых
в полосе 1,0–2,9 м ниже себя, поэтому ниже ~1 м в эту полосу попадает земля;
остальное — запас на вертикальную ошибку строя. Выбранная высота и причина
публикуются в `/mission/status` и в `altitude`/`altitude_reason` результата
`/mission/plan_result`. Карта двумерная: её препятствия считаются бесконечно
высокими, поэтому обход по высоте не планируется. Пустой путь при отказе
планировщика отзывает ожидающую и текущую миссию в интерфейсе ведущего.
Ручное управление при этом не прерывается.

Пакет `mission_planner` строит путь лидера через A* на восьмисвязной сетке.
Переход по диагонали запрещён, если хотя бы одна прилегающая ортогональная
клетка занята. Unknown (`-1`) считается препятствием, occupancy от 50 также
считается препятствием. Перед поиском применяется inflation по сумме
`formation_radius + safety_margin` с запасом в диагональ клетки: по половине
для площади препятствия и произвольной точки клетки маршрута. Это
консервативное ограничение, которое может закрыть узкий проход.
Край карты проверяется с тем же радиусом: выход строя за карту недопустим.

Радиус вычисляется по `/swarm/target_offsets` и ограничивается снизу
параметром `formation_radius`. Запас `safety_margin` учитывает габариты
аппаратов и погрешности. В штатном запуске нужна свежая геометрия строя.
Рост радиуса отзывает маршрут: после смены формы или масштаба пользователь
задаёт цель снова. Это не заменяет проверку физического тормозного пути.

API:

| Направление | Тема | Тип |
|---|---|---|
| Вход | `/map` | `nav_msgs/msg/OccupancyGrid` |
| Вход | `/mesh/states` | `swarm_interfaces/msg/SwarmState`, только `uav_id=0` |
| Вход | `/mission/goal` | `geometry_msgs/msg/PoseStamped` |
| Выход | `/mission/path` | `nav_msgs/msg/Path` |
| Выход | `/mission/status` | `std_msgs/msg/String` |
| Выход | `/mission/plan_result` | `std_msgs/msg/String`, JSON с goal_id, status и path_stamp либо reason |

Карта принимается reliable/transient-local, остальные входы reliable/volatile.
Карта, поза и цель должны быть в `map` (ENU); origin карты пока должен иметь
identity quaternion. Не выполняется скрытое преобразование TF. Timestamp
SwarmState проверяется по общим ROS-часам: старые и будущие позы отклоняются.
Используется штатная телеметрия лидера из mesh; нового источника ground truth нет.

При новой цели без карты, свежей валидной позы, при неверных данных или
недостижимости публикуются пустой Path и статус `REJECTED: <причина>`.
При успехе публикуется `PLANNED: <число точек>`. Первая точка — текущие X/Y
ведущего, последняя — точные X/Y цели. Между ними остаются только те центры
клеток A*, без которых прямой отрезок задел бы занятую (с учётом раздувания)
клетку или край карты. Проверка консервативна: касание угла клетки тоже
считается. Без этого 8-связный A* давал лесенку с поворотами через метр,
и ведущий тормозил и разворачивался на каждой точке; на свободной карте
маршрут теперь — один отрезок. Высота всех точек равна
запрошенной рабочей высоте. Это горизонтальный план на фиксированной высоте:
карта должна отражать препятствия на всей высоте и размерах строя.

Перепланирование происходит по новой `/mission/goal`. Изменение карты
или увеличение габаритов строя отзывает прежний маршрут. Планировщик не
выполняет takeoff, не отправляет setpoint и не управляет ведомыми.

Панель и S3 сопоставляют результат с отметкой отправленной цели и ждут
`accepted_path_stamp` от ведущего до вызова `/leader/mission`.
Текстовый статус сохраняется для совместимости и отображения.

Запуск после сборки и source окружения:

```bash
ros2 run mission_planner planner_node --ros-args --params-file src/mission_planner/config/mission.yaml
PYTHONPATH=src/mission_planner python3 -m pytest src/mission_planner/test -q
```

Размер карты ограничен `max_map_cells`, чтобы синхронное планирование не
блокировало узел на произвольно большой сетке. Для больших карт необходимы
асинхронный поиск и отдельная оценка времени работы.
